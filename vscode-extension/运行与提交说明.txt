Hot100 ACM：运行、手动测试与提交说明
适用版本：VS Code 插件 v0.2.5

一、开始练习
1. 在 VS Code 打开 /Users/qianye/Documents/Hot100 文件夹。
2. 点击插件左侧题目，每次选择语言。
3. 在题目顶部切换 ACM 模式或核心代码。
4. 先点击对应的代码编辑器，再执行下面的命令。
5. Mac：Cmd+Shift+P；Windows：Ctrl+Shift+P，打开命令面板，搜索完整命令名。

二、常用执行命令（在命令面板执行，不是终端 shell 命令）
Hot100 ACM: 本机运行示例
  执行题目示例，只做检查，不记录题目完成。
Hot100 ACM: 本机自定义用例
  手动修改输入和期望输出；执行一次自定义测试，不记录完成。
Hot100 ACM: 本机评测全部用例
  检查插件内全部用例；全部通过后更新插件中的完成状态和学习计划。
LeetCode: 登录
  登录力扣账号，供官网提交使用。
LeetCode: 提交代码
  核心代码模式：提交力扣官网；需要登录和联网。
  Python/C++/C 的 ACM 文件：该命令走本机全部用例评测，并非提交官网。

三、ACM 模式
代码目录：leetcode/acm/
写完整程序：读取标准输入、运行算法、输出结果。
C/C++ 保留 main；Python 保留 solve 和调用入口。
先执行“本机运行示例”，再执行“本机评测全部用例”。

手动测试：执行“Hot100 ACM: 本机自定义用例”。
弹窗会预填当前题目的一个用例，按题面输入格式修改 JSON。
例如第 1 题“两数之和”：
{"input":"4\n2 7 11 15\n9\n","output":"0 1\n"}
input 是完整输入；output 是期望输出，二者都必须是字符串。
换行用 JSON 中的 \n 表示；不要省略引号，不要用中文引号。

四、核心代码模式（力扣形式）
代码目录：leetcode/，不在 acm 子目录内。
只实现模板里的函数或类，不自己添加 main，不自行读取输入。
函数名、参数类型、返回值必须与模板一致。
执行“本机运行示例”或“本机自定义用例”，插件会创建调用驱动。
不要使用其他插件的通用“运行代码”按钮直接执行核心代码文件：
它通常缺少 main 或测试调用入口，直接运行不能代替本插件的判题。

核心代码手动用例，例如第 1 题：
{"args":[[2,7,11,15],9],"expected":[0,1]}
args 是按函数参数顺序排列的数组，expected 是预期返回结果。
链表、树、设计类有特殊编码：优先修改弹窗已有用例，保留其结构；
不要把所有题目都改成上述两数之和用例。设计类还需要 ops 字段。

本机全部通过后，若要官方通过记录：
先执行“LeetCode: 登录”，再执行“LeetCode: 提交代码”。
Mac：核心代码模式 Cmd+Option+S 对应提交。
Mac：Cmd+Option+T 对应测试；Python/C++/C 走本机示例测试。
其他语言保留原有官网测试、提交流程，本机评测目前支持 Python/C++/C。

五、查看测试结果
打开下方“输出”面板，通道选择“Hot100 本机评测”。
可查看编译器、通过数量、每个失败用例的信息。
本地 n/n 通过仅表示插件内用例通过，不等于力扣官方隐藏用例全部通过。
核心代码官网提交结果查看“LeetCode 判题结果”通道和通知。

六、你提供的 C++ 报错及修复
“vector 不是模板”：原始力扣模板省略了本地编辑器所需头文件或命名空间。
“无法打开 bits/stdc++.h”：它是 GNU 专用头，macOS 默认 Clang 不提供。
v0.2.5 为 C++ 文件补齐标准头、命名空间，替换 GNU 专用头；
树、链表模板的编辑器辅助声明仅在 IntelliSense 中启用，不参与官网判题。
原解题代码保留；已有本地 C++ 文件的修改前副本保存在本次输出的备份目录。

修复后执行 VS Code 的“开发人员: 重新加载窗口”。
若仍有旧的 C/C++ 诊断，可执行“C/C++: 重置 IntelliSense 数据库”。
缺少返回值、未完成 TODO 等提示仍需自己完成算法；不要忽略真实代码错误。
VS Code 是编辑器，实际执行由已安装的 Python 或 C/C++ 编译器完成。

七、重置计划
在学习计划页点击“重置学习计划”，确认后从零开始。
只清空计划记录；保留目标设置、通过状态、收藏、笔记和代码。
